01

العرض — View

Virtual Table / Logical Query Layer
👁️

الـ View هو جدول افتراضي يُعرَّف بناءً على استعلام SELECT، لا يُخزَّن فيه بيانات فعلية بل يعرض نتائج الاستعلام في كل مرة يُستدعى فيها. يُستخدم لتبسيط الاستعلامات المعقدة وتوفير طبقة أمان على البيانات.

تبسيط الاستعلامات — تحويل استعلامات معقدة إلى اسم بسيط قابل لإعادة الاستخدام
الأمان — إخفاء الأعمدة الحساسة وتقييد وصول المستخدمين
الاتساق — ضمان استخدام نفس المنطق في جميع التطبيقات
جدول افتراضي — لا يحتل مساحة تخزين حقيقية للبيانات
مثال عملي — SQL
-- إنشاء View لعرض بيانات الموظفين النشطين فقط
CREATE VIEW vw_ActiveEmployees AS
  SELECT
    e.emp_id,
    e.full_name,
    d.dept_name,
    e.hire_date
  FROM Employees e
  JOIN Departments d ON e.dept_id = d.dept_id
  WHERE e.status = 'ACTIVE';

-- استخدام الـ View كجدول عادي
SELECT * FROM vw_ActiveEmployees
WHERE dept_name = 'IT';

-- حذف الـ View
DROP VIEW vw_ActiveEmployees;

02

المشغّل — Trigger

Automatic Event-Driven Procedure
⚡

الـ Trigger هو إجراء يُنفَّذ تلقائيًا من قِبل قاعدة البيانات عند وقوع حدث معين (INSERT أو UPDATE أو DELETE) على جدول ما. لا يُستدعى يدويًا بل يُطلَق بشكل تلقائي.

BEFORE / AFTER — يُنفَّذ قبل الحدث أو بعده حسب الحاجة
سجل التغييرات — تتبع تاريخ التعديلات أوتوماتيكيًا (Audit Log)
القيود المعقدة — تطبيق قواعد العمل التي لا تدعمها القيود العادية
مزامنة الجداول — تحديث جداول أخرى تلقائيًا عند تغيير البيانات
مثال عملي — SQL
-- Trigger لتسجيل كل تعديل على رواتب الموظفين
CREATE TRIGGER trg_SalaryAudit
AFTER UPDATE ON Employees
FOR EACH ROW
BEGIN
  IF OLD.salary != NEW.salary THEN
    INSERT INTO SalaryLog
      (emp_id, old_salary, new_salary, change_date)
    VALUES
      (NEW.emp_id, OLD.salary, NEW.salary, NOW());
  END IF;
END;

-- عند تنفيذ هذا الأمر يُطلَق الـ Trigger تلقائيًا
UPDATE Employees
  SET salary = 75000
  WHERE emp_id = 101;
Audit Log التحقق من البيانات الحماية من الحذف مزامنة الجداول قواعد العمل التلقائية
03

الإجراء المخزّن — Stored Procedure

Named Reusable SQL Program
⚙️

الـ Stored Procedure هو مجموعة من تعليمات SQL مُخزَّنة في قاعدة البيانات بشكل دائم تحت اسم محدد، ويمكن استدعاؤها في أي وقت باستخدام CALL أو EXEC. تدعم المعاملات (Parameters) والمتغيرات والشروط.

إعادة الاستخدام — كتابة المنطق مرة واحدة واستدعاؤه من أي مكان
الأداء — تُجمَّع مسبقًا (Pre-compiled) مما يُسرّع التنفيذ
المعاملات IN/OUT — قبول بيانات مدخلة وإرجاع نتائج
معالجة الأخطاء — دعم DECLARE ... HANDLER للتعامل مع الاستثناءات
مثال عملي — SQL
-- إجراء مخزّن لتسجيل موظف جديد مع التحقق
CREATE PROCEDURE sp_AddEmployee(
  IN  p_name     VARCHAR(100),
  IN  p_dept_id  INT,
  IN  p_salary   DECIMAL(10,2),
  OUT p_new_id   INT
)
BEGIN
  -- التحقق من وجود القسم
  IF NOT EXISTS (
    SELECT 1 FROM Departments
    WHERE dept_id = p_dept_id
  ) THEN
    SIGNAL SQLSTATE '45000'
      SET MESSAGE_TEXT = 'القسم غير موجود';
  END IF;

  -- إدخال الموظف الجديد
  INSERT INTO Employees
    (full_name, dept_id, salary, status)
  VALUES
    (p_name, p_dept_id, p_salary, 'ACTIVE');

  SET p_new_id = LAST_INSERT_ID();
END;

-- استدعاء الإجراء
CALL sp_AddEmployee('أحمد بن علي', 3, 55000, @new_id);
SELECT @new_id AS 'رقم الموظف الجديد';
